## 品牌与设计令牌

Evidence Terminal：问题进入，公开记录被连接，结论保持可检查。

默认跟随系统的亮 / 深色偏好，系统切换时自动更新，无需刷新或保存主题覆盖。无明确偏好时使用亮色。通过 CSS `prefers-color-scheme` 与 `color-scheme` 同时控制页面和原生表单控件；不依赖 JavaScript 初始化，首屏即使用相应主题。

| 令牌 | 亮色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#f7f9f6` | `#0a0a0a` | 页面、抽屉与报告基底 |
| `--surface` / `--surface-2` / `--surface-3` | `#ffffff` / `#eef3ee` / `#e4ebe5` | `#111316` / `#171a1d` / `#1d2125` | 面板、表单、消息、引用块 |
| `--fg` / `--fg-2` | `#12231a` / `#35483d` | `#edf0ed` / `#c7ccc8` | 标题正文 / 次级正文 |
| `--muted` / `--faint` | `#526459` / `#5b6c61` | `#9ba69f` / `#858e87` | 辅助文字 / 编号 |
| `--border` / `--border-strong` | `#d7e0d8` / `#7b8c80` | `#282d29` / `#404741` | 分隔 / 结构边界 |
| `--accent` / `--accent-hover` | `#006b31` / `#005527` | `#00ff41` / `#5aff7d` | 主按钮、焦点、引用 / 悬停 |
| `--accent-dark` / `--accent-on` | `#e1f0e5` / `#ffffff` | `#003b12` / `#061108` | 选中态底色 / 主按钮文字 |
| `--warning` | `#946200` | `#ffb800` | 合成状态圆点 |
| `--danger` / `--danger-dark` | `#aa293a` / `#fff0f0` | `#ff6b6b` / `#351819` | 撤下、错误、待复核 |
| `--success` | `#23693b` | `#8fe6a5` | 有效状态文字 |

两套主题共用布局与证据状态。导航透明底色、网格、阴影、占位文字、焦点光晕、抽屉遮罩与危险按钮边框使用独立主题令牌，避免亮色页面残留深色组件。`--radius` 两种主题均为 `5px`。

参考：[MDN prefers-color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-color-scheme) · [MDN color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme)。

排版与节奏：

- 正文 `16px / 1.65`，中文用系统无衬线回退，标题允许放大。
- 等宽元信息 `12px`：编号、日期、来源代码、状态标签；不使用浏览器小字伪装精密。
- 结构线为 1px 细网格背景与 `--border` 分隔线，网格只组织真实内容。
- 动效强度 5/10：100–240ms，仅 `transform` 与 `opacity`；`prefers-reduced-motion` 下取消位移与动画速度。
- 触控目标不小于 44×44px；焦点环使用 `--accent`。

## 信息架构

### 首页 · 问题优先且精简

- 单行标题 `想了解谁？` 与一行说明 `查作品、经历和公开观点。每条结论都能点开出处。` 不堆营销要点。
- 研究问题是主体：必填 `textarea` 标签 `你想查什么？`，占位 `林舟如何设计 Lantern？`；主按钮 `开始研究`，次按钮 `看示例`。
- 输入有内容时出现 `清空`，清空后焦点回到输入框；`Cmd/Ctrl + Enter` 提交，忽略输入法组合与按键重复，且运行中不重复启动。
- 三个示例按钮直接填入问题并把焦点移回输入框；没有只改标签、没有输出的研究模式控件。
- 可选 `主页链接` 收在 `添加主页（可选）` 折叠中，helper 说明它只用于区分同名候选、示例不会访问。
- 每个活动视图只有一个紧凑的 `示例模式` 折叠；展开说明 `人物和资料均为虚构，暂不连接真实检索`。不隐藏合成性质，也不重复免责声明。
- 边界说明 `公开职业研究 · 适用范围` 放在页面末尾的次要折叠中。
- 出处示例区 `看看这句话的出处`：一条 Lantern 结论（`data-statement="mechanism-claim"`）、S1–S4 来源标签与出处预览，点击来源同步选中态与短引文，随后是 `看完整示例`。

### App 视图 · 全窗口研究工作台

- `#/app` 独立视图，由表单校验成功或 `打开工作台` 导航进入；`#/` 返回首页。App 视图隐藏营销导航与页脚。
- 桌面：左侧研究历史、中间 Chat 与结构化报告、右侧出处检查器；工作区高度对齐视口，正文区独立滚动。
- 窄屏：单列，历史与出处进入可关闭抽屉。正文滚动区与底部 composer 分占网格行，输入区不覆盖回答，也不占用过多高度。
- 用户问题位于研究过程之前；完成后的研究过程默认折叠，可展开查看 5 个可观察步骤与进度。
- 结构：用户研究问题 → 需要确认的同名候选 → 可观察活动（含 S4 无法访问与重试）→ 结构化回答 → 底部追问 composer 与快速追问。

### 报告结构

报告标题固定为 `这个人是谁` / `做过什么` / `查到的事实` / `可能的解释` / `还不确定`，末尾 `继续追问` 承载消息记录。正文删去重复定义，只删冗余表述，保留每条的出处引用、本人自述标识，以及事实、推断与未知的分列。

## 关键流程

1. 提交校验：`new URL` 解析公开主页（协议限 http/https 且要求非空 hostname，「https://」失败）；研究问题必填。错误就地显示、`aria-invalid` 标记、焦点移到首个失败字段，URL 错误会展开可选设置。
2. 身份确认：展示两个虚构的同名候选并保持独立；选择无 Lantern 关联的候选时拒绝启动脚本研究。
3. 可观察运行：逐步展示读取与核对步骤；暂停清空定时器，继续从当前步骤恢复，全程只有一个定时器。
4. 新建研究：清空消息、错误、运行定时器、报告、来源选择、撤销状态、导出提示与筛选，把来源与脚本状态复位。
5. 导出：报告存在前 `复制报告` / `下载报告` 保持禁用并在函数内再次拦截。

## 工作状态与进度

工作状态只使用中文，并按实际状态派生：`等待确认` / `正在查看资料` / `已暂停` / `已完成` / `N 处待复核`。不出现 `RUNNING`、`COMPLETE`、`LOCAL` 等内部代码。

进度条由已完成步骤数驱动，带 `role="progressbar"`、`aria-valuemin/max/now` 与 `aria-valuetext`。活动步骤使用 `待处理` / `正在查看` / `已完成` / `无法访问` 文字标签。运行指示点只在运行中且未暂停时显示并动画。`finishRun` 在运行标志为假时直接返回，因此完成只发生一次，额外的 `advanceRun` 调用是空操作。

## 撤回依赖模型

来源状态与结论依赖集中在 `index.html` 的 `sources` 与 `statementDefs` 中，UI 与导出共用同一份判定：

- S1 本人自述、S2 实际作品、S3 第三方观察为有效合成来源；S4 无法访问，始终排除在有效支持之外。
- 排除 S2 后，所有依赖 S2 的展示与导出同步变为 `待复核 · S2 已撤下`：
  - 已支持事实中的界面分区事实
  - 分析推断与机制结论
  - 2024-11 时间线事件
  - 此前与当前给出的脚本回答（依赖 S2 的消息追加待复核标记）
- 仅依赖 S1 / S3 的结论不被误标；恢复 S2 后状态一致恢复。
- 导出在每条受影响语句前直接写入 `**[待复核 · S2 已撤下]**`，不会把受影响语句留在 `查到的事实` 下不加限定。

## 来源检查器与抽屉

- 桌面检查器提供来源筛选（全部 / 本人 / 作品 / 第三方 / 异常）、原文、日期、位置、能说明什么、还不能说明什么、状态与操作；S2 可 `不采用这条来源` / `恢复来源`。
- 排除后在出处面板就地显示 `已不采用 S2，N 处结论待复核。` 与 `撤销` 按钮。撤销在桌面检查器与移动抽屉内都可用；抽屉打开时背景 `inert`，保持 Tab / Shift+Tab 陷阱，`Escape` 关闭并把焦点还给触发控件。
- 渲染来源详情会替换内容节点，因此重新渲染后会把焦点放回同一上下文里的操作按钮，避免焦点落到 `inert` 背景。
- 新建研究或重置会移除撤销入口，旧操作不会作用到新报告。
- 筛选无结果时显示空状态；排除 S2 后「作品」筛选为空。
- 首页引用在任意宽度打开展示抽屉；App 桌面引用展开右侧检查器，窄屏打开抽屉。视口变化会收起抽屉并同步检查器。
- 所有来源 URL 均为合成标识，原型不导航到伪网站。

## 导出与复制

- `下载报告` 用本地 `Blob` 生成 Markdown，包含合成声明、问题、结论、来源状态与限制，不写任何百分比可信度。
- `复制报告` 使用 `navigator.clipboard.writeText(buildMarkdown())`，仅在报告就绪时可用。
- 只有剪贴板写入成功后才提示 `报告已复制。`；被拒绝、同步抛错或缺少 API 时提示改用 `下载报告`，绝不谎报成功。
- 复制中禁用重复操作；新建研究后忽略旧请求的提示，复制期间排除来源则提示重新复制。
- 导出提示使用独立的 `#export-toast` 状态区域，不覆盖 `#desk-state` 的研究状态状态。

## 追问与草稿

- 三个快速追问按钮固定在底部 composer 上方，报告就绪后可见，可横向滚动并有渐隐提示。
- 点击快速追问立即发送对应的预设回答，不修改输入框里已输入的草稿。
- 手动发送：输入非空且报告就绪时，追加消息后清空输入框并把焦点留在 composer；发送失败（空内容或报告未就绪）时保留草稿。
- 与预设问句不完全一致的自由输入返回 `示例暂不支持这个问题。可以试试下方的三个追问。`，匹配使用精确字符串，不做关键词猜测。消息标签为 `你` / `示例回答`。

## 动效与可访问性

- 输入聚焦高亮；点击引用后用 220ms 强调选中的来源与原文。
- App、报告与新消息以 200ms 的 `opacity` / `transform` 进入。
- 进度与运行指示只在真实状态变化时更新；没有无限装饰动画、假打字机或人为延迟。
- `prefers-reduced-motion` 在首屏与偏好变化时都生效：动效缩短至几乎无位移；初始为减少动态时直接展示完整示例，运行中切换保留当前步骤及暂停状态。
- 所有交互有可见键盘焦点；正文对比度按 4.5:1 选择；状态同时用文字与边框形状表达，不只依赖颜色。
- 对话与抽屉使用 `role="dialog"` / `aria-modal`；列表使用 `listbox` / `option` 语义。
- 桌面导航保持单行，`.button.nav-mobile { display: none }` 使用足够的特异性，避免桌面同时出现冗余 `菜单` 按钮；`940px` 及以下才显示。
- 无远程字体、远程脚本、图片或网络请求。

## 原型真实性边界

- 只有本地 HTML/CSS/JS：没有真实采集、检索、模型推理、流式事件、持久化或后台服务。
- 研究对象林舟、项目 Lantern 与 S1–S4 均为合成材料；不抓取 `example.org` 等 fixture 域名。
- 运行状态是脚本演示，不伪造实时速度、用户量、覆盖率或任何指标。
- 预设回答与 `待复核` 标记只演示状态传播与依赖撤回，不构成研究方法结论。
- 正式实现必须读取同一 canonical report；本原型不是第二份报告事实来源。

## 本地验证

在仓库根目录：

```bash
python3 scripts/check_design.py
npm --prefix design/web/qa test
```

`check_design.py` 是静态一致性检查；`prototype.test.cjs` 使用 jsdom 在离线环境驱动原型脚本，覆盖校验、快捷键与清空、剪贴板成功 / 失败 / 门禁、撤回与撤销、进度计数与暂停、导出门禁、抽屉焦点与新建研究复位。两者不测量网络、模型或 provider 行为；真实浏览器结果另见 [验证记录](VALIDATION.md)。
