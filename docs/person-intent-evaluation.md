# 综合人物研究及评估

状态：2026-09-23 方法与评估规格提案；未运行模型对照，未获得人工裁决。补充 [研究方法](research-method.md) 与 [评估设计](evaluation.md)，不替换现有运行时回归。

**主任务已校正：** 用户通常只问“深度调研某个人”。系统应主动研究重要经历、作品与贡献、关注的问题、公开表达与互动、相关公开生活侧面，并形成综合细致的报告。人物特点决定深入哪里；阅读推荐、采访与合作准备是补充用途，不能替代主任务，也不是用户开始前必须选择的分类。

## 综合报告的共同要求与人物差异

共同检查身份与时效、重要经历、作品和个人贡献、观点与变化、公开表达和社交互动、相关其他侧面及认识边界。按真实材料决定篇幅，不为填表编事实，也不能只答一个容易的问题就算完成深度调研。

人物差异放在评审侧：对翻译/信息分享者查原创和转述归属；对产品创作者查表达、产品与商业活动的关系；对研究者查合作贡献、论文与公开主张；对长期写作者查不同阶段、注意对象和读者互动。它们是需要调查的问题，不是预定人格结论。被测系统默认只收到简短主查询和身份种子，才能检验是否主动发现重要面向。

**社交风格单独核查：** 发布方式与互动方式分开。完整讨论需保留原帖、提问/异议、回复、时间和后续；只读文章不能推断如何合作，只看到关注或转发不能认定私交。跨场景反复出现才提出有限的模式解释，单例只描述该次事件。抽样记录平台、时间窗、排序、选择理由和不可读部分，既不只选赞美，也不为平衡强找负面。没有互动材料时单列覆盖缺口，不编一个亲切、内向或强势的人设。

## 研究的成果

好报告使用户对一个具体的人形成**更准确、更具体、可修订、与当前意图有关的理解**。这可以服务于学习、阅读、交流、作品理解或合作前的问题准备；不要求每一次好奇都转化成商业决策。

事实正确是必要条件。只返回几条不会出错的履历，或者不停说“证据不足”，仍可能没有完成任务。报告应说明：相对用户已知内容，多知道了什么；原有解释哪里需要调整；哪些疑问仍然值得保留。不能用迎合用户好恶、稀奇八卦或人格标签充当增量。

## 默认综合研究，具体用途作为补充

输入记录 `person_anchor`、`intent`、`known_context`、`time_scope`、`desired_output`、`material_scope`。这些是研究简报字段提案，不是已实现 API。`intent` 默认 comprehensive_person_research，其余上下文可缺省；不要求用户先提出子问题。身份确有歧义再补身份线索。下表用于有额外用途时调整重点，不替代综合覆盖。

| 意图 | 必须得到 | 条件相关 | 常见无用输出 |
|---|---|---|---|
| 初次理解 / 持续阅读 | 代表作品、反复处理的问题、观察其方法的入口 | 公开生活写作、审美、价值张力 | 简历、名人赞美、订阅量 |
| 学习一种能力 | 具体做法、适用条件、代价、可尝试的练习 | 失败复盘、非典型作品、读者反馈 | “执行力强”“多读他的文章” |
| 理解经历 / 观点变化 | 当时材料、后续修正、仍保持的部分、其他解释 | 自述与第三方观察 | 把先后顺序写成心理因果 |
| 采访 / 交流准备 | 对方已回答什么、尚未回答的具体张力、带出处的追问 | 相关作品过程和上下文 | 五个换谁都能问的问题 |
| 合作前问题准备 | 与项目有关的作品与可归属角色、协作过程、关键未知、低成本验证 | 有公开依据的亲历观察 | 用作品质量担保私下诚信或适配 |
| 授权自我研究 | 不同材料视角带来的遗漏与误读、事实修订 | 用户明确选择的生活与私人材料 | 默认导入全部档案、以用户印象代替事实 |

必要性检验：**删掉这条信息，会不会使一个重要人生阶段、作品、表达/互动特点或认识边界消失？** 若不会，再判断是否服务于用户附加用途，优先省略重复枝节。职业之外的材料可以必要；公开可得本身不是必要性的理由。

## 研究过程

1. **写下起点。** 以姓名和身份线索开始，先确认人和公开材料分布。用户已经提供的用途与已知内容作为补充，不要求用户先回答研究问卷。将本地观察与公开事实分开。
2. **以作品或事件为中心采集。** 优先身份锚点、代表作、过程记录；按问题补较早材料、较新材料、不同场景及有依据的第三方观察。不是每题机械凑齐五类来源。
3. **重建选择。** 情境 → 表达 → 可观察行动 → 结果 / 后续。只记录有证据的选项和代价，不编造未走道路、内心挣扎或团队贡献。
4. **主动寻找能改变解释的材料。** 查失败、修订、适用条件和相反场景。无反证时写“本次范围内未发现”，不得为了显得平衡制造争议。
5. **合成并停止。** 给出有出处的理解、替代解释、关键未知和与意图相符的产物。关键问题已覆盖且连续两轮没有新增相关证据时停止；预算或访问阻塞则返回缺口，不声称穷尽。

检索优先级由“能否减少关键不确定性 × 可核验性 × 获得可能性 ÷ 成本”帮助排序；这只是人工规划启发式，不输出伪精确概率。新检索必须指向某个仍未解决的问题。

## 同一个人必须允许不同的合格答案

产品理念研究，重点可能是声明与实际格式的关系；采访准备，则要找声明没有回答的取舍；合作准备，则还缺协作和交付信息。三题都输出同一份完整人物百科应视为意图失败。

区分四种认识：公开记录支持的事实；当事人的自述；分析者基于明确证据的解释；仍待核实的问题。可以提出有洞察的解释，不把保守等同于禁止分析。每个重要解释应附支持、限制及什么材料会改变它。

## 现有十个练习为什么不能衡量产品价值

工作台种子位于 `apps/web/src/server/review-seed.ts`。它们是 8 个行为练习 + 2 个身份/引用练习；来源与候选均为开发时生成的合成示例。

- 六题的差异集中在明显错误，例如把计划当交付、把先后当因果；易形成“选保守答案”捷径。
- 其余四题已有较细差别，但仍主要是少量短材料里的判断，不涉及开放检索或真实研究意图。
- 没有用户已知内容、来源选择成本、跨时间理解、研究后追问和有用性验收。
- 不能测出“两份回答都事实正确，哪份帮助更大”；也不能测出检索遗漏。

保留为操作教学与安全回归。新的研究任务独立版本化，历史人工标注及案例 hash 不覆盖。不能只把虚构姓名换成名人，继续沿用二选一常识题。

## 评估单元与三个轨道

单元是 **人物 × 用户意图 × 已知内容 × 时间截面 × 可用材料**，不是一个人名。

案例首先保留用户自然会说的话，例如“帮我了解这个人”“见面前聊什么”“这次合作和原先印象不同”。意图、来源要求和判分点留在评审侧，不能把预期发现塞进提问，再把模型复述当成研究能力。除非任务确有约束，不固定字数、证据条数或必须得到的正面评价。作者拟定的合理场景与真实用户日志必须分别标记；后续应用真实问题及反馈逐步替换拟定场景。

| 轨道 | 输入 | 能评什么 | 不能声称 |
|---|---|---|---|
| 冻结材料综合 | 同一来源快照包；隐藏评分准则 | 理解、引用、取舍、解释 | 开放搜索能力 |
| 实时检索 | 同一问题、种子、时间/请求/成本上限 | 查询规划、证据发现、失败处理、综合 | 同语料因果比较 |
| 多轮更新 | 初始材料 → 新证据或用户修正 | 撤回依赖、更新范围、保留仍成立部分 | 把模拟用户当真实用户收益 |

每个案例至少记录：独立人物组、问题、意图、已知内容、时间截面、可读来源及定位、必要观察、允许的不同解释、不得跨越的推断、具体评分点、未读/不可访问项、预算、版本与评审状态。

没有材料再分发许可时，真实研究包只保存在 Git 忽略的本地目录；公共仓库放通用契约和原创合成示例。来源卡必须说明是原文、短摘录还是研究者摘要；摘要不自动代替原文。

## 怎么评分

先过硬门：严重错人、伪造来源/引文、材料越权、把无依据的严重负面推断写成事实。保留所有错误计数；硬门失败不能靠文风抵消。

综合人物研究先逐项记录四种状态：已说明且有依据；提到了但笼统或证据不够；已有可答材料却遗漏或说错；当前材料无法判断。附报告原句或遗漏位置，区分材料不可访问、系统未检索到和未发现公开材料。未知不算通过，也不全部算研究失败。以下 0/1/2 仅为后续比较的映射提案；尚未冻结为自动评分器。事实项必须有有效定位；解释项允许不止一个答案。

| 维度 | 2 分的表现 | 不能刷分的方式 |
|---|---|---|
| 意图完成 | 交付题目要求的理解/选择/追问 | 无关完整履历、长报告 |
| 信息增量 | 指出相对已知内容新增或修正什么 | 重述简介、迎合原评价 |
| 证据与归属 | 人物、时间、原文和结论匹配 | 来源多、域名多、星标多 |
| 解释质量 | 连起作品/行动与情境，检验其他解释 | 人格形容词、因果故事 |
| 校准与更新 | 回答可答项、准确保留未知、修订恰当 | 全部拒答、机械找反面 |
| 交付用途 | 给可执行练习、可引用问题或清楚的阅读路径 | 万能建议“持续观察” |

综合案例使用六个共通覆盖项和各人物的具体检查点，先分别报告，避免用某个强项抵消重要遗漏。这些维度是检查视角，不再与观察点重复加总。总分、发布阈值、不同意图权重先不冻结。报告逐项分布、严重错误、可答项完成率与核查用时；不以单一总分宣布系统可靠。

## 防止把新评估继续做成自证

- 先写问题与准则，后运行候选；评分材料不放入模型输入。案例作者答案可做分析示例，不作为唯一标准答案。
- 配对基线使用相同模型、预算、输入与输出长度上限，保留所有失败/超时。实时轨道记录查询和原始 URL，不只存最终报告。
- 使用两个真实候选再盲评，不预写一个蠢答案；A/B 顺序随机且稳定。打平、都不好、无法判断均有效。
- 至少加入事实正确但泛泛、准确却遗漏关键限制、全部未知、长而偏题、文笔较差却有增量等对照，用来检查 rubric 本身能否区分质量。手工对照不算模型实验。
- 去名字后仍能凭作品和情境说明价值，防名气光环；同源重发不加分；不同意图应改变信息取舍；补新材料应只更新受影响解释。
- 同一人物、别名、来源家族及多轮变体放同一 split。名人公开案例只作 discovery，另用授权的稀疏材料任务检验泛化。同一人的多个问题不能当多个独立人物样本。
- 人工事实裁决与“对我是否有帮助”分开。熟悉当事人的人提供重要纠错，但其偏好和私人印象不是全局真值。

## 对当前工作台的影响

综合人物研究规格与已有两份答案评审分别保存。任务规格包含简单查询、身份种子、共通检查、人物检查和已知材料缺口；没有候选时保持待运行、未评审，不能为了入库编造两份回答。模型输入导出只包含查询与身份种子，评审标准独立导出。API 与页面实现范围以 [工作台契约](annotation-workbench.md) 为准。

旧案例、hash 与历史人工标签保持不变。任务规格入库不代表完成研究或评测；来源探索轨迹、多轮更新、真实候选执行和任务观察点评分仍需后续实现。不能用 free-text “参考答案”冒充已经实现的评估器。

## 方法依据

- [FActScore](https://aclanthology.org/2023.emnlp-main.741/)：借用原子事实支持率；它不回答用户是否更理解这个人。
- [DeepResearch Bench](https://arxiv.org/abs/2506.11763)：区分报告质量与检索/引用；通用深研维度仍需按人物意图具体化。
- [DeepResearch Bench II v3](https://arxiv.org/abs/2601.08536v3)：参考专家报告导出的细粒度准则；本项目本轮没有专家裁决，不继承其验证效果。
- [The Second Half](https://ysymyth.github.io/The-Second-Half/)：问题定义与真实效用是研究观点，支持重新设计评估的动机，不构成本项目收益证据。
- [τ-bench](https://arxiv.org/abs/2406.12045)：借鉴多轮交互及明确目标状态；其工具任务成功率不能直接迁移成人物理解评分。
