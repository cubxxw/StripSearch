# 产品设计

状态：v0.1 设计提案。实现与效果均待验证。

## 用户真正购买的结果

研究者准备一次采访、理解一位作者的经历，最昂贵的部分通常不是拿到更多网页，而是判断网页说的是不是同一个人、故事是否被实际行动支持、结论能否站住。StripSearch 的产品假设是：**让研究更容易核查、更容易修正，比让报告更长更有价值。**

“一个人最真实的部分”不能作为可验证的产品承诺。可以研究的是：在明确情境里，此人留下了什么行动记录，哪些选择反复出现，什么反例会改变我们的解释。不要输出“诚信 87 分”或从沉默推断动机。

## 首个用户与任务

| 用户任务 | 输入 | 有价值的交付 |
|---|---|---|
| 采访准备 | 已知公开主页、3–5 个问题、时间范围 | 事件时间线、观点变化、可引用的追问、尚未证实项 |
| 作品研究 | 作者与明确作品 | 贡献链、版本与后续维护、团队和个人角色区分 |
| 授权自我研究 | 自己的公开链接和选择导入的本地档案 | 能追溯的经历整理；本地证据与公开证据分开标识 |

不以招聘自动筛选、人格诊断、全面私人背景调查为 MVP 场景。没有证据支持的负面评价尤其不能变成产品事实。

## 默认体验

1. **输入尽量少。** 姓名、一个已知主页、要回答的问题。上下文与时间可补充。
2. **先给身份卡。** 显示目标与已核实主页；有歧义则给独立候选和最有区分力的一条待补充线索。
3. **先交付可核查片段。** 正在研究时也可返回已核验的有限结果、未解决问题和花费；草稿片段标为 provisional。
4. **报告先回答问题。** 每个结论旁有来源和状态；可切换时间线、作品或摘要作为首屏。
5. **点开就能复核。** 人物 → 事实/事件 → 短引文与定位 → 原始 URL。无法读取时直说，不用搜索摘要伪装正文。
6. **新证据可修订。** 被误归属的材料撤下后，依赖它的结论自动失效，保留版本差异。

“完成”表示完成约定的研究范围；不表示已经知道这个人的一切。没搜到材料可能是没有公开、不可访问或检索能力不足，三者不能混同。

## 值不值得做

已有通用 Deep Research、人物查找与 OSINT 工具。重新包装搜索和长报告的差异很弱。本项目值得验证的增量是：**持续的身份归属、可回溯的行为证据、错误撤回，以及针对这些问题的公开评估。** 这还是产品假设，不是市场结论。

先与普通搜索研究工作流做盲测。如果新增结构没有减少严重错误或人的核查时间，就简化为可嵌入的证据核验库；如果用户实际只需要人物查找，就不扩建深度分析系统。明确失败方向可以减少无效开发。

## 三条不变量

- 来源多不等于来源独立；自述明确不等于事实已经独立证实。
- 身份正确和说法正确是两个问题；所有新材料都需要归属判断。
- 输出样式可以配置，人物索引、证据状态、时间截面与未知不能被模板隐藏。
