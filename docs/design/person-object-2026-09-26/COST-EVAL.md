# 成本、评测与落地门槛

## 1. 成本主张

“日常愿意用”需要低的**每个合格任务成本**，同时保持质量、等待时间和纠错负担。仅降低 token 单价，或通过大量 partial 降低平均费用，不证明产品可用。建议先证明一次研究可低成本完成，再用同一 Person 的复用和增量更新降低高频使用成本。

用户付费价格、供应商实际成本和方案中的预算上限是三件事。首版可采用固定基础额度/单次明确价格，预算内自动选择来源；额外付费研究由用户明确触发。暂不在官网公布尚未经过质量和成本验证的极低零售价。

## 3. 降本顺序与硬约束

1. 已有链接先读对应账号，再检索缺口；已经取得的正文不再向第二个供应商买一次。
2. Person 及 Source 按权限、版本与新鲜度复用；追问先查已有证据，切换格式不再调用模型。
3. 分段抽取成小型证据索引，稳定 tools/system/schema 前缀，避免每轮回传全站全文。
4. Flash 为默认，思考强度和输出长度按任务设置；高成本升级必须在已承诺预算内有证据收益。
5. 每轮按信息增益选择下一个动作；固定调用、页数、候选数、输出 tokens、deadline 和金额上限。

初始内部默认采用“日常标准”档。用户无需选三种深度；档位用于实验与预算控制，只有额外研究才在 UI 显示具体价值和费用。省钱不能靠完全取消必要反证核验。

按 cache miss、当前高峰价和单次最大输出预留；并发 reservation 使用事务。供应商费用上界未知时只能承诺调用次数/页数，不能声称严格金额封顶。outcome_unknown 的在途请求冻结预留，先对账，不无声重试。每阶段最多一次修复，同因连续失败两次停止扩展。

成本账最小字段：tenant/run/action/model/provider、priceVersion、tokens hit/miss/output、requests/pages、estimate/reserved/actual/unknown、currency、providerRequestId、outcome。失败、取消和压缩也计入，不只记录成功报告。

## 4. 验证实验

先冻结 60 个身份与来源边界离线案例：明确主页 10、同名 10、内容角色 10、账号迁移/组织/冒名 10、缺页/限制 10、注入/撤回/权限 10。60 例只能发现问题，不能证明总体低错误率；发布时给样本量和置信区间，不报脱离样本的 99.9%。

再准备 20 个有授权/许可材料的 live 任务，覆盖中文/英文、资料稀疏/丰富、个人主页/纯姓名、网页/社交/长采访；同输入、同预算比较：现有一次性方案、直接 DeepSeek 受限 loop、DSH 新 Controller。使用盲评，保留失败与 partial，独立人工标签不是模型生成的自评分。

**合格任务的分母先冻结。** 每题由独立标注者给出适用维度、必须覆盖的关键问题/证据、可接受 unknown 和禁止断言；在运行模型前冻结 rubric。合格任务须身份正确、所有适用关键项已处理、关键断言支持、恰当保留 unknown、无严重错误且完成约定步骤。支持率分母为报告中全部可核查原子断言，不允许挑选好看的部分。正确拒答单列，不当成完整报告成功；全部启动任务含 failed、cancelled、partial、重试及未知费用均进入总体成本和成功率。

覆盖采用适用 rubric 项的加权完成率，并与同预算基线配对比较；不能以只输出一条安全事实刷高支持率。初始门槛为全部关键项已处理，整体覆盖不低于基线；样本不足以判断差异时写证据不足。成本/合格任务 = 全部尝试总成本 ÷ 合格任务数；合格数为零则不可计算，绝不记零成本。

| 指标 | 建议初始门槛或报告方式 | 失败如何处理 |
| --- | --- | --- |
| 严重错人/凭空证据 | 冻结对抗集 0 个未解决案例；公开样本量 | 阻止发布，补反例与回归 |
| 原子 claim 引用合法性 | 100% 有效 ID、可见权限、未撤回版本 | 确定性拒绝快照 |
| claim 语义支持率 | 独立人工盲评，建议起始目标 ≥95%，单列核心结论 | 不支持者降为 unknown/删除 |
| URL 路径人工打断 | 明确可读 profile 集目标 0 次重复身份确认 | 改路由，不放宽错人约束 |
| 歧义路径 | 必要消歧能正确提出，不能为降干预率强行自动选人 | 保留候选并接受 abstain |
| 首次响应 | 本地提交反馈目标 <200ms；网络识别另计 | 不用 fake progress 伪装 |
| 首个有价值结果 / 完成 | 实测 p50/p95；初始体验目标 30 秒 / 3 分钟，不是 SLA | 先交付可用 partial 并说明限制 |
| 成本 | 总成本/合格任务数；同时报全部尝试成本、重试、unknown 与 p95 | 调整覆盖、缓存与商业假设 |
| 用户核查负担 | 与基线相比，完成任务耗时和纠错次数下降 | 无增益则减少结构和额外研究 |
| 输出一致性 | HTML/JSON/PDF 的 claim/evidence/revision 完全一致 | 禁止发布格式分叉 |

未来可考虑标准任务全部可变成本 p50 ≤0.20 美元、p95 ≤0.50 美元作为实验目标；是否足以定价必须结合合格率、平台数据费和毛利。不能拿上表模型+Exa估算直接宣布达标。

## 5. 四批落地

| 批次 | 可交付结果 | 必须通过的门槛 |
| --- | --- | --- |
| P0 单输入与路由 | 已支持主页直接启动、名字候选、输入恢复与无多余来源选项 | URL/帖子/同名/组织/不可读/登录/取消状态；未支持能力如实说明 |
| P1 Person 与快照 | schema v2、归属/证据/原子 claim、CAS、legacy adapter | 错人分离、撤回传播、权限、三格式语义与版本一致 |
| P2 DSH 纵向闭环 | 固定 profile、有限循环、工具网关、预算账、checkpoint | kill/restart、取消迟到结果、outcome_unknown、注入、日志字段禁用 |
| P3 成本质量与扩展 | 20 例同预算 live 对照、采访/平台适配、增量追问 | 可复核质量/成本/时延；达标后灰度，再谈订阅和更多宿主 |

P0/P1/P2 在此是分期编号，不是漏洞严重性。每批先更新共享 schema/契约，再实现渲染器，使用 feature flag 保留现有运行路径。扩平台按逐端点可用性和实际增益推进，不默认采购全平台数据。

本轮交付是上述设计和交互原型；没有执行这些未来 live 实验，也没有将任务分期标成已开发完成。
