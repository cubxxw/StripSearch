# 产品与交互设计

## 1. 产品定义

面向想理解公开创作者、研究者、创业者与技术作者的人，解决“资料分散、同名难辨、读完仍不了解”的问题。默认任务是综合理解，不要求用户先写研究提示词；会面准备、作品研究和持续阅读是同一人物资料上的用途。

核心表达：**从一个名字或链接，开始了解一个人。** 用户应在五秒内知道输入什么，提交后立即看见输入被接收，随后看见真实发现。不能承诺“知道一个人的一切”，也不用长报告、来源数量或人格分证明深度。

普通个人只处理明确授权材料。邮箱/手机号作为用户已获授权的消歧线索，默认脱敏、不批量枚举注册站点、不公开导出。访谈、作品、公开互动和可核查职业活动是研究重点；不扩展到泄露库、住址定位、匿名身份揭露或自动招聘排序。

## 2. 当前设计为什么失焦

实际页面有可保留的基础：明确的“想了解谁”、醒目的主行动、来源核对与修订说明、手机单列。缺点不是缺更多视觉效果，而是把系统实现暴露成输入任务。

| 观察 | 对用户的影响 | 新设计决策 |
| --- | --- | --- |
| 用户需选 GitHub / Exa | 要先理解采集工具，错误选择阻断链接 | 服务端解析与路由；消费者入口无来源选择 |
| 必填“你想查什么”，主页折叠 | 已知人物仍要编问题、重复填 URL | 一框接收姓名、主页、帖子和自然语言 |
| 首屏大表单、重复示例和边框 | 视觉重点变成配置，产品结果缺席 | 输入区域 + 一个可以点开出处的合成结果片段 |
| 手机 CTA 约占 180px 高度 | 把输入与结果拉远，增加滚动 | 正常 48–52px 高，键盘出现时保持可见 |
| 下方主要解释“如何核查” | 用户仍不知道能得到怎样的理解 | 展示“公开作品 → 有据认识 → 认识边界”的真实结构 |
| 数据以 run 为中心 | 每次像重新搜索，无法积累 | 人物页是长期入口，研究是其上的一次更新 |

代码依据：`apps/web/src/client/index.html`、`main.ts:254-338`、`render.ts:90-173`。线上观察与本地版本不同；这里仅对二者共同的界面结构下结论。

## 3. 方向树与取舍

D0 不变量：少输入、找对人、读得懂、可追溯、可纠正。

| 分叉 | A | B | 推荐与可证伪理由 |
| --- | --- | --- | --- |
| D1 产品主张 | 人物入口：从一个线索建立理解 | 阅读入口：从关注人物的新内容开始 | 首访 A 更直接；已关注人物的回访 B 更有价值 |
| D2 页面路径 | 输入 → 身份锚点 → 人物资料 | 输入 → 完整研究配置 → 长报告 | 选前者；后者仍将工作转嫁给用户 |
| D3 首屏构图 | 单输入和一句结果承诺，后置证据片段 | 阅读列表为主体，紧凑输入位于顶部 | 两者做成可见 A/B；不把配色差异冒充结构差异 |
| D4 结果载体 | 单列人物阅读页 + 按需证据侧栏 | 默认全屏人物关系图谱 | 选前者；图谱是内部关系模型，必要时再成为探索视图 |

设计建议 A 为新访客默认，B 为有真实订阅内容后的回访页面。B 在本轮只是合成状态，不能推出后台订阅已支持。若用户测试显示回访仍以临时查询为主，则保持 A，B 降为“已保存人物”。

空间语言为轻量编辑式阅读：少容器、清晰标题、可靠的内容节奏；不使用黑客终端、科幻 HUD、装饰性网络图。参考 WhiteBridge 的输入与候选机制、Readwise 的上下文阅读、Tapestry 的时间顺序聚合、Linear 的主内容与辅助面板分工；不复制任何一家完整视觉身份。

## 4. 输入与身份确认契约

提交才启动请求，粘贴时只在本地识别类型，不因剪贴板变化偷偷外发。输入之后的首个工具环节始终存在；能自动完成就不要求用户确认。

| 输入 | 系统动作 | 用户看到什么 | 何时询问 |
| --- | --- | --- | --- |
| 个人主页 URL | 规范化、读取可用的平台稳定账号 ID、确认页面类型；独立网站用内部 anchorId + URL/内容版本 | 正在了解此账号或主页，旁边可“更换对象” | 页面不可读、组织主页、冒名冲突 |
| 帖子/文章/视频 URL | 读取发布者、作者、被采访者关系 | 明示正在研究的是作者/受访者 | 多人访谈、转发、文章同时涉及多人 |
| 姓名 + 公司/作品 | 查询候选并交叉核对 | 足够唯一则直接进入人物页 | 多个合理候选时给 2–3 个卡片 |
| 只有姓名 | 低成本候选检索 | 有区分线索的候选列表 | 询问一个公司、作品或主页线索 |
| 多个链接 | 对账号逐一解析并比对 | 同人已证实时汇入；否则分组 | 不静默假设所有链接属于同一人 |
| 邮箱/电话 | 在授权范围内精确匹配允许的数据源 | 脱敏标识和匹配状态 | 无授权匹配能力则请求公开主页 |
| 短链接/不可读链接 | 受限解析跳转并检查 URL 安全 | 说明读不到哪一部分，保留输入 | 可补一个主页或继续有限资料 |

**个人主页是明确的研究起点，不是跨平台同人的证明。** URL 规范化相等只确认目标账号；同名、同头像、相同用户名不能独立触发人物合并。自动归属采用明确互链、经过核验的官方职业主页、稳定平台标识及相互独立的上下文证据；冲突优先于相似度。没有足够证据的账号保持候选，可不打断主线继续研究已确认账号。

候选确认只问“你指的是哪一位”；每卡显示姓名、公开职业线索、一个辨识链接和选择动作，不暴露概率、十几个筛选项或让用户审判每条来源。选择只表达用户意图，后续材料仍需证据核验。

## 5. 逐屏设计

### 首页

导航只保留品牌、已保存人物（登录后）和账号入口。H1“想了解谁？”，副文案“输入姓名或公开主页，查看经历、作品与公开表达。”输入有可见 label，兼容中文姓名和 URL，不能设成仅允许 URL 的 input。主按钮“开始了解”，一个“看合成示例”入口。

首屏不放 provider、模型、平台勾选、研究深度向导、图谱、来源数量、内部标注工具和工具调用成本。实际收费产品在按钮附近清楚显示本次价格或已含额度；成本细账放详情，不能借极简隐藏收费。

登录沿用账号体系：保留待提交文本，登录后恢复，提交幂等。未获得公开试用额度前不承诺免登录真实研究。首页示例可匿名离线阅读，与真实研究有明确区别。

### 已提交与研究中

输入原位变成研究标题与对象卡，无跳到空白后台。先显示接收、再显示已读取的身份锚点及内容；同一页逐步补充。不展示模型思维链、token 跳动、伪百分比或无限“即将完成”。

状态文字对应真实事件：正在核对主页、正在读代表作品、正在核对出处、已有部分结果。只给“停止”和必要的“更换对象”。可收起活动详情查看已读/未读范围；页面刷新后能恢复同一个 run。

### 人物阅读页

桌面正文 680–760px，右侧证据面板仅在点击引用后出现；手机单列，来源抽屉关闭回到引用位置。

1. 人物头部：姓名、当前可支持的职业/作品描述、已确认主页、资料截至时间。若身份仅限账号则写“基于该账号的公开资料”。
2. 快速理解：3–5 条有出处的认识，事实、自述、解释在句子层区分；证据不足则少给，不凑满。
3. 代表作品与转折：选择少量能解释此人经历的记录；时间线按有效时间组织，缺日期保留未知。
4. 公开表达与互动：摘取上下文完整的观点、回应、修正，展示前提、行动及后续；不从语气推断心理健康或固定人格。
5. 仍不确定：只呈现会影响当前理解的缺口、反例与未能读取的关键资料；空栏目默认不显示。

“综合了解 / 会面准备 / 作品研究”改变同一 revision 的信息投影。会面准备输出由已知材料导出的可问问题；若需要新证据，明确“需要补充研究”，不能静默重跑全网。追问先引用已有证据，再决定是否付费扩展。

### 来源与导出

引用点开：原文短摘录、作者角色、原始 URL、日期、定位、资料状态、为何支持此句；可标“不是这个人”或“不采用来源”。恢复、撤回影响和修订版本在同一处可见。

导出只显示 HTML、PDF、JSON，保留 Markdown 兼容入口。格式切换不重新调用 LLM，不新增事实。PDF 首版可由服务端同一 HTML 模板生成；设计原型的浏览器打印另作标识。默认私有下载，分享为显式动作。

## 6. 少判断的边界

| 自动完成 | 收进详情 | 必须主动可见 |
| --- | --- | --- |
| 输入类型、平台路由、已确认账号读取、去重、分页选择、预算内查询 | provider 名、工具步骤、token、价格账、弱候选、原始字段 | 身份不确定、核心反证、关键来源不可读、费用/范围变化、研究中断 |
| 可复用缓存、格式转换、低价值来源停止 | 技术错误码、完整调用收据 | 用户需要恢复/补充/停止时的明确动作 |

不是每个低置信结果都弹窗。无法消除但不影响主体的问题保留 unknown；无法确定研究对象才请求用户。把干预率降到最低必须以错人率不恶化为前提。

## 7. 视觉、移动与状态

使用现有绿色情绪资产，去掉网格背景与大量盒子。建议纸白 `#F7F8F5`、正文 `#18241F`、强调 `#176546`，色值是设计起点，最终检查对比度。中文系统字体、正文 17px/1.7，辅助文字至少 13px；间距 8/12/16/24/40/64px。变化程度 5/10、动效 2/10、密度 3/10。

主控件至少 44px，输入与按钮在 390px 内不横向溢出；支持键盘、可见焦点、IME 组合输入、错误播报、减少动态效果。仅内容到达与焦点变更使用短动效；不能靠动画遮盖加载或伪造进度。

空白、多个候选、无匹配、无正文、部分结果、超时、预算耗尽、取消、恢复、身份更换、来源撤回均有确定文案和后续动作。“完成”只表示约定范围已处理，不表示信息完整无缺。
