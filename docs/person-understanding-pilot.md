# 人物理解任务集 · 首轮协议 v0.1

状态：设计完成，未运行；真实人物卡片与材料保存在 Git 忽略的本地研究目录。没有人工 gold，没有模型质量结论。本协议补充 [评估设计](evaluation.md)，不替代已有数据集，也不把既有 60 题扩展计划标为完成。

## 产品问题

首轮服务于公开作者、创作者、研究者和创业者的初次深读与交流准备：用户能否基于证据理解此人做过什么、表达过什么、哪些解释仍然站不住，并选出下一篇值得读的原作和一个值得追问的问题？不判断是否录用、投资或信任此人。

任务空间采用 `用户任务 × 研究问题 × 身份难度 × 证据环境 × 时间截面 × 推断边界`。人物是承载问题的样本，不是评分对象。“底色”“品味好”“靠谱”不是 gold。

## 首轮结构

- 20 道主任务：12 道 discovery、4 道 judge calibration、4 道 holdout candidate。
- 同一人物、可能的别名、同源证据、问题变体与所有 mutation 放在同一分区。证据采集后还要检查来源簇；仅按姓名分区不足以保证无泄漏。
- 当前 4 道候选的题目已向设计者展示，不能声称盲测。正式验收另由未参与调参的维护者冻结未曝光的题目与证据；否则按已知验收题报告。
- 对照变体属于原题：多一次运行不增加独立样本数。20 题不是 20 个被验证的总体代表样本。
- 身份混淆、时效变化、真实冲突只在采集确认后贴标签；不能为了填配额虚构人物经历。人工删减材料形成的是受控稀疏环境，不能说该人物在公共网络上资料稀少。

## 一道题的最小合同

Agent 可见：目标种子、消歧线索、问题、截止时间、允许来源、任务级输出与预算。裁判可见：冻结证据、原子要求、禁止推断、接受多种合法答案的规则。人评可见：匿名候选答案与同一证据版本。

全量设计卡不是 Agent prompt；运行时必须单独导出输入，隔离 gold、mutation、私有熟人观察和评审记录。当前文档隔离只是设计，不代表已经有执行层访问控制。

每题必须记录：`task_id / family_id / split / protocol_version / question / cutoff / source_policy / required_outputs / primary_failure / required_evidence / rubric / allowed_unknowns / readiness / review_status / execution_status`。实际运行还需冻结 `input_hash / source_manifest_hash / rubric_hash / model_version / agent_revision / budget / tool_config`。

期望输出按题收敛，不统一强制长传记：身份边界、有关的行动/作品、归属明确的公开表达、可修订解释、原作与追问、未知。资料不足时允许只返回身份澄清；不能为凑三项经历而生成事实。

## 证据包与参考答案

事实表区分 `observed_fact / attributed_statement / bounded_inference`；每项记录人物归属、允许表述、来源定位、时间、来源独立性和依赖。本人说过 X 的证据不能直接证明 X。

另有冲突表、不可回答表和失效依赖表。两份材料时间不同、讨论范围不同或术语不同，不自动构成冲突。开放检索中“未在 gold 列表”不等于错误；新事实须另核验，必要事实 recall 的分母在运行前冻结。

每题增加一份能通过要求的参考回答以证明可解；允许不同措辞和不同证据充分的解释。它是可行性见证，不用于文本相似度评分。研究者不能完成参考回答的题需修改或搁置。

时间分开记录 `event_time / published_at / updated_at / retrieved_at / observed_version_at / cutoff`。严格的“当时可知”题要求截止日前存在的内容版本；今天读取一篇早期文章，不能自动证明正文从未更改。无法锁定版本就标时间无法核验，不能假装冻结。

来源返回 403、删除或需要登录属于可用性问题；不能单凭无法访问判为伪造。保留原 URL、重定向 URL、允许的短摘录与定位，合法存档另存 hash。无许可不重发第三方全文。

## 评分：门禁、质量、裁判覆盖分开

四个 rubric 标签固定为 `pass / fail / insufficient_evidence / not_applicable`，首版取消模糊的“部分满足 = 0.5”；需要半分的复合要求拆为两个原子项。

- `pass`：证据充分，满足这一项；按要求保留未知也可通过。
- `fail`：答案违反要求或遗漏明确要求；“没写”不是裁判证据不足。
- `insufficient_evidence`：裁判材料/定位不足，暂时无法判断。不是事实错误，也不是通过。
- `not_applicable`：按冻结题目条件事先确定；答案少写了内容不能事后豁免。动态条件的适用性由证据决定，不能由 Agent 的输出决定。

排除预先成立的 N/A 后，总权重为 W；pass 权重为 P；无法核验权重为 U。报告 `下界 = P/W`、`上界 = (P+U)/W`、`裁判覆盖率 = 1-U/W`。下界只是保守已证实满足率，不是把 U 宣判为事实错误。W=0 时题目无效。

首轮通过条件：全部门禁已判定且通过、所有必须项 pass、下界 ≥ 80%、裁判覆盖率 ≥ 90%。两项阈值是可校准的试运行规则。即使非必须项有 U 而仍通过，也须显式显示 U，不能宣称全部断言已核验。

结论采用顺序：已确认致命错误或必须项 fail → fail；否则门禁/必须项有 U → needs_adjudication；否则上界 < 80% → fail；否则达到通过条件 → pass；其余 → needs_adjudication。超时/空输出算运行失败并进入所有启动任务的分母；环境故障另记原因，不从总成功率静默删除。另报有效题目的质量通过率。

门禁包括：重大身份误归属、捏造事实/来源、重大结论引用不支持、重大推断被当成事实、违反明确资料范围、截止日后信息改变结论、应撤销的关键结论仍被采用。细小引用定位错误扣对应项；预先标为关键的断言缺失有效支持必须失败，不能用平均分掩盖，也不把所有格式瑕疵叫作伪证。

## 质量维度

基础六维继续按 [评估设计](evaluation.md) 报身份、事实、时间、证据、分析和边界。额外记录两组可核查指标：

1. **人物理解增量**：是否连接了可归属事件；是否考虑反例/替代解释；结论强度是否与证据匹配；撤回/新增证据后，更新范围是否正确。单篇文章不强制总结“反复出现的倾向”。
2. **阅读与交流价值**：原作推荐是否存在并相关；问题是否可追溯且不带虚假前提；用户核查时间、错误数、是否选择继续读。偏好盲评与事实正确性独立，不推导“这个人值得信任”。

引文支持既报 claim–source 对支持率，也报去重断言的有效支持覆盖率；十条弱引用不能掩盖核心断言无支持。无输出时 precision 为 N/A，可回答项覆盖为 0。只拒答不能取得高总体表现。

## 执行与 judge 校准

冻结材料轨测理解/归属/引用；实时检索轨测来源发现与完整链路。固定材料包含全部正文时，不声称测到搜索能力。实时轨必须保存查询、候选与读取失败；未冻结来源的两次运行差异不能全部归因于 Agent。

先做 5 道代表题的证据和可行性检查，再完成 20 题采集与评审。首轮比较普通研究 prompt 与 StripSearch，同模型、同输入、同来源/预算，各题至少 3 次；披露实际成本，不调用未授权的付费服务。结果按任务和人物族聚合，报告次数与区间，四题验收只能作冒烟。

Judge 校准选 5–10 份基准回答，由两位独立评审标注后仲裁。每份做日期、公司、错人、错引、自述升级、删不确定性等单变量错误，以及文风、段落顺序、合法释义等意义保持变体。真实人物错误版本仅限本地明确标记的裁判测试，不发布为研究结论；优先对合成材料做危险断言 mutation。

冻结配对、随机展示顺序、隐藏系统名与版本，单独测错误检出率、正确答案误杀率、judge 弃判率和人评一致性。风格变体应基本保持内容标签，新增真实反证应改变受影响结论；后者不等于“每条新信息都要改结论”。Judge 版本也须冻结；小样本通过只能允许辅助预标，不允许替代关键门禁的人评。

## 当前交付边界

本轮只有协议、20 张设计卡、候选登记、待核查证据提案与空白标注模板。真实人物名单不进入公开评估目录；没有写入运行数据库，没有生成用户评价，没有运行模型或发布 benchmark。现有 `npm run eval` 范围不变。

参考：[Anthropic Agent Evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)支持从少量真实失败任务起步、可解参考答案、平衡任务与人工校准；本文的题目分配、阈值、评分区间和产品维度是本项目设计选择，不是该文的行业标准。
